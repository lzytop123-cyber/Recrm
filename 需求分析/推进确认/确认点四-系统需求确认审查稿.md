## 2. 关键结论

### 2.1 产品与功能

1. 产品按一个公司、一个入口和统一身份设计，主系统、线索池和AI知识库共享组织、账号和关键业务关系。
2. 100项功能覆盖经营看板、客户线索、合同资金、项目交付、工单协作、人员与会议排期、OKR绩效工资、员工生命周期、AI知识库和运行审计。
3. AI产品销售、AI定制开发和自媒体代运营分别使用已确认的六阶段、九阶段和七阶段交付旅程，不强行共用同一交付模板。
4. 会议排期覆盖内部培训和外部沙龙，关联讲师档期并同步飞书日历，不包含会议室管理。

### 2.2 交互与终端

1. 逻辑产品采用角色化统一工作台，31个页面承载FR-001至FR-100，10条核心路径覆盖主要端到端业务。
2. PC网页端承载完整管理功能。
3. 手机端承载日报、线索跟进、任务与工单、审批、排期确认、消息提醒和个人看板；复杂配置、批量导入导出和敏感财务管理保留在PC端。
4. 飞书工作台作为统一入口，用户使用飞书身份进入系统。

### 2.3 权限与敏感数据

1. 权限同时受到公司、部门、岗位、业务角色、项目、工单、对象责任和知识授权范围约束。
2. 系统管理员默认不自动查看业务明细；临时授权必须限定目的、范围、有效期并留痕。
3. 客户联系方式、合同金额、成本利润、绩效申诉、工资、员工档案和知识内容按敏感级别控制。
4. 明文查看、跨部门查询和批量导出分别授权；兼岗发生职责冲突时由独立角色复核。

### 2.4 数据与迁移

1. 系统承载44个数据对象、212项逻辑属性和68组对象关系，状态、版本、引用和审计要求已经明确。
2. 客户不迁移，由员工重新录入；历史合同不迁移；员工档案和组织人员数据重新创建。
3. 现有项目从飞书多维表格迁移，采用字段映射、试导入、校验、正式导入、差异隔离和失败补迁流程。
4. 公司未制定具体保留年限前，数据只归档、不自动物理删除。

### 2.5 性能、可用性与安全

1. 首期容量基线为100个有效内部账号、50人同时在线。
2. 常规操作P95不超过2秒，复杂查询不超过3秒，经营看板和知识检索不超过5秒。
3. 月度可用性不低于99.5%，RTO不超过4小时，核心数据RPO不超过1小时。
4. 普通会话空闲30分钟失效，核心故障5分钟内被识别。
5. 越权成功事件目标为0，高敏感关键操作审计覆盖率为100%。

### 2.6 飞书集成

1. 不接入企业微信、电子签、独立财务软件和独立邮件系统，相关协作统一使用飞书CLI。
2. 飞书用于身份与工作台、项目多维表格迁移、考勤、日历、授权工作群、云文档、通知及财务负责人指定的协作来源。
3. 身份变动15分钟内生效；会议日历5分钟、工作群知识15分钟、云文档30分钟完成同步或返回失败状态。
4. 飞书邮箱首期只用于系统通知，不自动采集邮件正文和附件。
5. 飞书财务资料只作为待核验材料，不能自动形成到账、成本、工资或发放结论。

### 2.7 验收

1. 41条用户故事均有正常场景验收条件。
2. 45条关键规则与异常覆盖线索、财务、项目、工单、排期、绩效、员工、知识、权限、数据、性能和集成边界。
3. 31个页面均有原型验收条件，要求展示核心数据、核心操作、状态反馈、异常空状态和无权限状态。
4. 10条核心路径均有端到端完成标准，不能以静态孤立页面代替业务闭环验收。

## 3. 已确认事实

1. 系统仅服务单一公司，当前约48名内部员工，不支持多公司或外部客户账号。
2. 线索全员可录入；公共线索按权限抢领；重点商机由市场销售中心分配；每个客户同一时点仅一个主负责人。
3. 公共线索开放时间和发放条数可配置；每人每天最多抢领20条，保护期内线索最多100条；员工只能释放本人当前领取或被分配的线索。
4. OKR按月管理，公司到部门强制对齐，个人至少一项目标对齐部门；绩效影响绩效工资或奖金，不改变固定工资。
5. 综合管理部负责绩效规则、校准和申诉；财务负责工资核算、复核和发放；双方完成后发布工资条。
6. 首期纳入入职、转岗、离职、劳动合同、员工档案和考勤，不纳入完整招聘候选人管理。
7. AI知识库只采集获批工作群、云文档和企业文件，不采集个人聊天；采集授权与查看权限分离。
8. 首期采用云端部署，不建设本地私有化环境。

## 4. 推断内容及处理结果

C层累计记录18项设计推断，均已在对应阶段提交用户确认并转为当前系统需求基线：

2. C5的7组非功能建议：容量、响应、可用性、恢复、会话、故障发现和兼容安全基线。
3. C6的7组集成建议：身份、日历、知识、通知同步时效，以及邮件和财务协作边界。

这些推断的确认表示可以作为当前需求和验收输入，不表示已经完成技术可行性验证或上线实现。
