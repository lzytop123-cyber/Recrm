# CRM+OKR公司管理系统非功能需求分析

## 1. 分析说明

| 项目 | 内容 |
|---|---|
| 阶段 | C5 非功能需求分析 |
| 输入模式 | 模式1：标准输入 |
| 适用范围 | 单一公司、约48名内部员工；主系统、线索池和AI知识库统一入口 |
| 终端基线 | PC网页端承载完整功能；手机端承载高频执行功能；通过飞书工作台进入 |
| 部署基线 | 首期云端部署，不建设本地私有化部署 |
| 本阶段边界 | 定义可验证的质量目标，不规定技术架构、产品选型、安全实现或压测方案 |

## 2. 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 上线必须满足；不满足将导致核心业务不可用、数据错误或敏感信息风险 |
| P1 | 首期应满足；短时偏差可降级处理，但必须可发现和恢复 |
| P2 | 优化目标；不阻断首期上线，但应保留监测和改进空间 |

## 12. 验证口径

1. 性能指标应在脱敏且接近正式规模的数据下统计P95，并同时记录并发用户数、数据量和失败率。
2. 权限、安全和审计指标按角色、对象范围、敏感字段、终端和临时授权组合验证，不能只测试页面菜单是否隐藏。
3. 可用性与恢复指标通过故障记录或恢复演练验证，不能只以服务进程启动作为恢复完成。
4. 飞书依赖异常需要覆盖超时、重复回调、权限失效、部分成功和恢复补偿；具体能力与限制在C6定义。
5. 手机端仅验收本文件明确的高频范围，不能以手机端缺少PC管理功能判为不通过。
6. 项目迁移容量在取得实际飞书多维表格后复核；在此之前不承诺未知附件和关联规模。

## 13. 建议基线与未定参数

- 100个有效内部账号、50名同时在线用户、P95响应目标、99.5%月度可用性、RTO 4小时、RPO 1小时、30分钟空闲会话以及5分钟故障发现均为C5根据当前48人规模提出的首期建议基线。
- 项目多维表格的实际记录、附件与关联规模尚未取得，迁移容量需要在C6或实施准备阶段复核。
- 公司正式的数据保留年限和隐私制度尚未提供；在制度确认前继续执行C4已确认的“只归档、不自动物理删除”。
- 本阶段不指定云服务商、部署拓扑、数据库、安全产品、备份实现或飞书CLI具体调用方式。

## 14. 审查结论

- 已覆盖性能、容量、可用性、安全、审计、易用性、兼容性、可维护性和合规性。
- 已把PC完整功能、手机高频功能、飞书工作台入口和首期云端部署转化为可验证约束。
- 已保持单公司、内部用户、飞书CLI、敏感数据分级和外部系统边界不变。
- 建议数值需经用户确认后，才能作为后续集成与验收条件的正式基线。
