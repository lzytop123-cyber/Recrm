# CRM+OKR公司管理系统验收条件分析

## 1. 分析说明

| 项目 | 内容 |
|---|---|
| 阶段 | C7 验收条件分析 |
| 输入模式 | 模式1：标准输入 |
| 验收对象 | 41条用户故事、100项系统功能、31个页面、10条核心路径，以及已确认的业务规则、权限、数据、非功能和飞书集成要求 |
| 验收边界 | 定义业务完成标准和可评审原型条件；不编写测试脚本，不设计自动化测试，不假定飞书多维表格具体字段 |

## 2. 统一完成标准

一项需求只有同时满足以下条件才可判定完成：

1. 正常场景产生正确业务结果，并关联责任人、状态、时间和来源。
2. 无权限、规则不满足、数据缺失、重复提交、状态冲突和外部同步失败均有明确结果，不产生错误业务事实。
3. 关键状态变化、敏感查看、导出、更正、发布、删除、授权和拒绝均可追溯。
4. 页面中的核心数据、操作、反馈、空状态和无权限状态均可被业务人员评审。
5. PC端承载全部功能；手机端只验收已确认的高频执行范围。
6. 飞书异常不能静默覆盖本系统主记录，也不能把未知状态显示为业务成功。
7. 汇总、明细、导出及绩效工资计算使用同一生效口径和规则版本。

## 4. 规则、异常与边界验收条件

## 5. 原型验收条件

所有页面均须展示其权限内的范围/筛选、核心对象状态、待办或异常、关联记录与历史；操作后必须出现成功、处理中、失败、冲突或无权限反馈；无数据时显示原因和可执行下一步。

## 6. 核心路径验收

| 路径 | 验收口径 |
|---|---|
| PATH-001 员工每日执行 | 从个人工作台看到当天事项，能够记录日报并处理本人待办；冲突和无权限有反馈 |
| PATH-002 线索录入到跟进 | 完成录入、查重、责任取得、保护期和跟进；重复、额度和超期分支可验证 |
| PATH-003 成交到立项 | 成交信息、合同、应收与项目启动条件连续；缺失项不能跨越 |
| PATH-004 项目计划到收尾 | 基线、任务、分类交付、成果、验收、财务核对和复盘完整关联 |
| PATH-005 工单闭环 | 创建、分派、处理、确认、评价、升级和重开按配置执行 |
| PATH-006 会议讲师排期 | 排期、讲师确认、冲突、日历同步、变更和取消保持一致 |
| PATH-007 月度目标到工资条 | 规则、目标、证据、初评、校准、申诉、锁定、核算、复核和发布顺序不可跳过 |
| PATH-008 员工入转离 | 身份、组织、岗位、权限、责任、考勤和历史关系按生效时间一致 |
| PATH-009 知识授权到检索 | 来源申请、审批、采集、治理、权限过滤和来源展示连续；个人聊天不进入 |
| PATH-010 异常到纠偏 | 看板异常可下钻至授权事实，并形成负责人、期限和关闭结果 |

## 8. 映射与覆盖结论

- AC-US-001至AC-US-041逐一对应US-001至US-041，41条用户故事均有正常场景完成标准。
- AC-RULE-001至AC-RULE-045覆盖线索、合同财务、项目、工单、排期会议、绩效工资、员工、知识、权限、数据、性能和飞书异常边界。
- PAC-001至PAC-031逐一对应C2的PAGE-001至PAGE-031，并通过各行FR引用覆盖FR-001至FR-100。
- PATH-001至PATH-010均定义端到端完成口径，原型评审时不得只展示静态孤立页面。
- AC-NFR和AC-INT覆盖C5、C6首期确认基线。
