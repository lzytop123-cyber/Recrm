## 2. 权限总体原则

1. 权限绑定组织岗位、业务角色和项目角色，不把具体人员姓名写死在流程中。
2. 同一员工可以兼任多个角色；角色任命、项目参与和生效期限必须可追溯。
3. 董事会拥有全公司经营数据查看和重大事项决策权限，但不替代执行岗位完成日常业务录入。
4. 梁军所对应的经营管理角色负责公司日常经营统筹和跨部门协调，但不能修改财务独立确认结果、法律审核结论或董事会决议。
5. 财务部、法务部和董事会秘书部直属董事会，不继承经营管理层的行政审批关系。
6. 部门负责人管理本部门人员、目标、任务、工单和资源；涉及其他部门时按项目、工单或授权流程协作。
7. 员工默认只能操作本人负责、本人参与、被分配或被明确授权的业务对象。
8. 项目角色只在指定项目范围内生效，不改变员工行政汇报关系。
9. 客户、财务、绩效工资、员工档案和知识内容按最小必要范围展示。
10. 所有关键授权、审批、分配、查看敏感信息、更正和导出均保留操作轨迹。

### 3.3 跨部门业务角色

| 角色 | 生效范围 | 核心权限 | 约束 |
|---|---|---|---|
| 项目发起人 | 指定项目 | 发起立项、提出目标和成员需求、确认业务结果 | 不能单独确认财务启动条件或替代项目负责人 |
| 项目负责人 | 指定项目 | 计划基线、任务、成果、风险、变更、验收、结项和复盘 | 不修改财务确认结果、法务审核结论或成员行政归属 |
| 项目成员 | 指定项目 | 查看项目必要信息，处理本人任务、成果和工时 | 不查看无关客户、合同、工资或其他项目数据 |
| 项目财务 | 指定项目 | 查看合同和项目财务信息，维护成本、收款和财务结论 | 由财务岗位人员担任，不由项目负责人替代 |
| 项目律师 | 指定项目或事项 | 查看合同、变更、验收和合规材料，形成法律意见 | 不修改商务、财务或交付事实 |
| 项目技术/需求/开发/测试/运维角色 | 指定AI定制项目 | 按项目职责处理需求、方案、开发、测试、上线和维护任务 | 作为单一公司系统内的项目功能角色，不形成子公司组织或租户 |
| 工单发起人 | 指定工单 | 创建、补充、确认、评价和规定期限内重开 | 不分派目标部门处理人 |
| 工单处理人 | 指定工单 | 受理、处理、提交结果和申请转派 | 不能替发起人确认关闭 |
| 直属负责人 | 直属员工范围 | 目标确认、绩效初评、人员安排和异常说明 | 不执行综合管理部校准锁定或财务工资核算 |
| 知识来源/内容责任人 | 指定来源或内容 | 申请接入、治理、纠错、下架和提交删除 | 接入授权、技术接入和最终删除职责分离 |
| 会议组织者 | 本人负责会议 | 创建、变更、取消内部培训或外部沙龙会议 | 时间或讲师变化需重新确认，不管理会议室 |
| 系统管理员 | 账号、组织配置和集成运行 | 账号组织基础、技术接入、同步状态和授权配置 | 默认不承担业务审批或修改业务结论 |

## 6. 数据权限矩阵

| 数据范围 | 适用角色 | 范围规则 | 下钻边界 |
|---|---|---|---|
| 全公司治理范围 | 董事会 | 可查看全公司经营、项目、资金、人员和风险数据 | 敏感明细仍按治理用途访问并审计 |
| 全公司经营范围 | 经营管理负责人 | 可查看经营、客户、项目、部门执行和绩效结果 | 不修改财务、法务和董事会独立结论 |
| 董事会直属专业范围 | 董事会秘书、法务、财务 | 仅访问本专业职责所需公司数据 | 通过事项、合同、项目或财务关系下钻，不获得无关业务编辑权 |
| 部门范围 | 部门/中心负责人 | 本部门员工、目标、任务、工单、排期和部门参与项目 | 跨部门数据仅限共同项目、工单或明确授权部分 |
| 团队范围 | 小组负责人 | 本小组人员、线索、任务、排期和指标 | 不自动获得同中心其他小组全部明细 |
| 个人责任范围 | 普通员工、销售、交付岗位 | 本人录入、负责、领取、被分配或被授权对象 | 不能通过搜索、导出或关联对象绕过范围 |
| 项目范围 | 项目发起人、负责人、成员、项目财务、项目律师 | 仅指定项目及完成职责所需关联对象 | 客户、合同、财务和员工字段按项目角色进一步裁剪 |
| 工单范围 | 发起人、处理人、目标部门负责人、抄送人 | 指定工单及其流转、成果和必要关联信息 | 关联项目或客户只展示工单处理必要信息 |
| 知识授权范围 | 全体员工、内容责任人 | 公司公开、部门、岗位、指定人员四类范围叠加 | 搜索结果返回前过滤，无权内容不暴露标题和摘要 |
| 本人私密范围 | 员工本人 | 本人工资条、绩效明细、申诉、档案和考勤 | 其他员工默认不可见；负责人只见履职所需部分 |

## 7. 关键业务授权与审批规则

### 7.1 组织与日常事项

1. 执行岗位发起日常事项，小组负责人或部门负责人按组织层级处理。
2. 部门负责人的任免和重大岗位调整由经营管理负责人处理，达到董事会重大岗位标准时提交董事会。
3. 综合管理部办理员工入转离；部门负责人确认业务交接；系统管理员只在有效结论后调整账号和组织关系。
4. 工作流按岗位角色定位处理者；当前任职人员变化时不修改流程定义。

### 7.2 线索与客户

1. 全体员工可录入线索；普通公共线索由有抢领权限的员工在开放窗口内抢领。
2. 市场销售与客户中心负责人或被授权的线索管理角色配置开放时间、发放条数、抢领范围和重点商机分配。
3. 每个客户只保留一个主负责人；重点客户或筛选后的商机由市场销售中心分配。
4. 每个人只能释放本人当前领取或被分配的线索；重新分配、错误合并撤销和延期审批需要授权业务角色处理并保留历史。

### 7.3 合同、资金与项目

1. 客户负责人或解决方案销售发起合同；法务和财务并行审核；由有效授权人签署。
2. 报价及折扣由市场销售中心负责人处理；超过董事会设定标准时提交董事会。未配置标准前系统不得自行假设数值。
3. 项目发起人提交立项；部门负责人确认资源；PMO完成分级和资料检查；经营管理负责人处理跨部门项目；重大项目提交董事会。
4. 财务独立核验合同和约定收款条件；项目负责人不能自行把项目标记为财务条件已满足。
5. 项目预算及追加成本由项目负责人发起，部门负责人和财务处理；超标准事项升级经营管理负责人或董事会。
6. 范围变更由项目负责人发起，PMO登记并组织影响分析，商务、交付和客户确认；重大变更升级。
7. 交付验收由项目负责人组织，内部商务责任人记录客户确认，交付负责人确认成果，财务据此处理结算节点。

### 7.4 OKR、绩效与工资

1. 综合管理部维护绩效规则版本、组织校准、处理申诉并锁定结果。
2. 管理层制定公司目标；部门负责人承接部门目标；员工和直属负责人确认个人目标。
3. 员工提交证据；直属负责人评分；综合管理部校准；员工确认或申诉。
4. 一票否决必须具备证据，并由直属负责人、综合管理部和经营管理角色共同确认。
5. 未完成申诉不得锁定绩效；财务只能读取已锁定绩效结果和发放系数。
6. 会计办理工资核算，财务主管完成复核，出纳记录发放；绩效与财务流程完成后发布工资条。
7. 已发布工资条发生错误时发布更正版本，原版本继续保留且不可覆盖。

### 7.5 排期与会议

1. 培训部或被授权的内部组织者创建内部培训会议；市场销售中心或被授权业务组织者创建外部沙龙会议。
2. 讲师确认本人档期；部门负责人只处理冲突、替代人员或升级，不替讲师确认。
3. 会议组织者可以变更或取消本人负责会议；时间或讲师变化需要重新确认。
4. 系统管理员处理飞书日历技术同步异常，但不能擅自改变会议业务时间、讲师或参与范围。

### 7.6 AI知识库

1. 工作群由群主或业务责任人申请、部门负责人批准；云文档由所有者或知识责任人申请、部门负责人批准。
2. 系统管理员仅负责技术接入，不代替来源授权或内容审批。
3. 内容责任人可纠错和下架；删除原始内容需来源所有者或部门负责人确认。
4. 默认只采集授权后的内容；历史回溯需单独批准；个人聊天不得采集。
5. 检索前按公司公开、部门、岗位和指定人员范围过滤。

## 8. 职责分离约束

| 编号 | 业务场景 | 不相容职责 | 控制要求 |

| SoD-002 | 收款 | 销售协调与到账确认 | 销售不能自行标记到账，到账由财务确认 |
| SoD-003 | 项目启动 | 项目申请与财务条件确认 | 项目负责人不能绕过财务核验启动正式交付 |

| SoD-005 | 工单 | 处理结果提交与发起人验收 | 处理人不能替发起人直接确认关闭 |
| SoD-006 | 绩效 | 员工证据、直属评分、综合校准和财务核算 | 同一角色不能替代全部环节完成结果锁定和工资处理 |

## 9. 敏感信息与审计要求

### 9.1 敏感信息展示

- 客户手机号、联系信息和沟通记录仅对当前负责人、协作角色和授权管理者展示。
- 合同金额、收款、成本和利润仅对治理、财务、商务责任和项目必要角色展示。
- 员工绩效评分、申诉、工资和档案按本人及职责角色分别展示；部门负责人不默认查看员工工资明细。
- 知识内容按内容授权范围展示；无权用户不获得标题、摘要、命中数量或来源是否存在的信息。
- 法务、财务和董事会材料按事项范围展示，不能因为属于同一直属层级而相互继承全部权限。

### 9.2 强制审计操作

以下操作必须记录操作人、业务角色、时间、对象、操作前后结果、原因、授权或审批依据：

- 角色任命、权限变更、临时授权和账号停用。
- 线索合并、撤销合并、分配、重新分配、释放、退回和保护期延期。
- 合同审核、收款确认、开票、退款、成本利润更正及导出。
- 项目立项、基线确认、重大变更、验收、结项和取消。
- 工单转派、升级、关闭和重开。
- 会议变更、取消和飞书同步异常处理。
- 绩效规则生效、评分、校准、一票否决、申诉、锁定和更正。
- 工资核算、复核、发放、工资条发布、查看和更正。
- 员工入职、转岗、离职、档案和考勤异常处理。
- 知识来源授权、历史回溯、纠错、下架、撤权、删除和越权拒绝。
- 查看、导出或批量处理高敏感数据。

## 10. 例外授权方案

以下内容为完成权限闭环所需的最小推断方案：

1. 系统管理员默认只有账号组织、技术接入、同步运行和权限配置能力，不因管理员身份自动查看业务明细。
2. 临时代理或跨部门授权必须填写业务目的、授权对象、数据范围、生效与失效时间、批准角色；到期自动失效并保留历史。
3. 明文查看敏感字段、批量导出和跨部门查询与普通页面查看分开授权。
4. 员工兼任多个角色时可以获得职责所需权限集合，但如果同一事项形成职责冲突，系统仍要求另一名具备独立角色的人员完成复核或批准。

> 来源：推断内容  
> 输入模式：模式1  
> 推断依据：组织文件明确要求按角色配置、不写死姓名，并强调财务、法务、PMO和业务职责分离；但未逐项规定系统管理员默认数据范围、临时授权、敏感导出和兼岗冲突处理，因此提出最小控制方案供确认。

## 11. 审查结论

- 当前权限结构覆盖C1的100项功能和C2的31个页面承载范围。
- 母公司48人组织结构、岗位职责、项目角色和专业部门独立性已进入权限模型。
- 单一公司范围保持不变，未建立子公司组织、租户或数据隔离规则。
- 已任命人员只用于记录当前岗位关系；实际流程始终引用岗位或业务角色。
- 综合管理部负责人、新媒体各组具体负责人、客户PM、Kunlin岗位人选及客户开发组长正式人选保持“待定”，不影响按岗位配置权限。
- 董事会重大事项金额、折扣和预算偏差阈值未预设具体数值；系统仅要求阈值后续可配置并按角色升级。
