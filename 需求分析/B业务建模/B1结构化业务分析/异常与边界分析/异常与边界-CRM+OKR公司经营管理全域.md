# CRM+OKR公司经营管理全域 - 异常与边界分析

## 1. 基本信息

- **阶段**：B1.6 异常与边界分析
- **分析对象**：单一公司在线索、合同资金、项目交付、跨部门工单、人员会议排期、绩效工资、员工管理和AI知识治理中的异常、替代流和补偿流
- **标准输入**：已验证的B1.1业务过程、B1.2数据流、B1.3数据字典、B1.4逻辑数据模型和B1.5业务规则
- **输入模式**：模式1：标准输入
- **分析日期**：2026-07-21
- **边界声明**：本产物定义业务异常触发、处理责任、补偿、恢复条件和最终状态；不设计技术容灾、异常代码、重试算法或基础设施架构。

## 2. 异常分类与处理状态

### 2.1 异常分类

| 分类 | 说明 | 典型场景 |
|---|---|---|
| 数据异常 | 信息缺失、重复、矛盾、过期或错误 | 线索误合并、合同金额错误、汇总与明细不一致 |
| 规则异常 | 达到数量、时限、状态或权重边界 | 抢领超20条、保护期超100条、绩效权重不等于100% |
| 流程异常 | 前置条件不足、审批缺失、非法跳转 | 未核验收款即启动项目、未锁定绩效即核算工资 |
| 资源异常 | 人员、时间、能力或计划发生冲突 | 讲师档期冲突、项目成员同时被占用 |
| 外部依赖异常 | 外部事实或外部系统不可用/不一致 | 飞书日历同步失败、到账凭证待核验 |
| 权限与合规异常 | 无权查看、修改、审批、采集或删除 | 越权释放他人线索、采集个人聊天、越权查看工资条 |
| 结果争议 | 客户、员工或责任部门不认可结果 | 客户验收未通过、绩效申诉、工单结果退回 |

### 2.2 影响等级

| 等级 | 业务含义 | 处理要求 |
|---|---|---|
| L1提示 | 不影响当前业务继续执行 | 提示责任人补充或确认，可继续非受控操作 |
| L2阻断 | 前置条件不足或违反明确规则 | 阻止进入下一受控状态，责任人修正后恢复 |
| L3升级 | 已影响客户、交付、资金、绩效或跨部门时限 | 通知负责人并按既定升级链处理 |
| L4敏感 | 涉及工资、数据安全、严重客户影响或重大失职 | 冻结争议结果、保留证据并由指定管理角色联合处理 |

### 2.3 异常处理状态

`已发现 → 待责任人处理 → 处理中 → 待确认 → 已恢复/已关闭`

约束：

1. 异常关闭必须记录处理结论和责任人。
2. 被阻断的主业务保持原状态，不得伪装成已完成。
3. 补偿操作不删除原记录，应以更正、撤销、重新确认或新版本恢复。
4. 涉及申诉、验收、工资、知识授权和敏感数据的异常，未确认前不得自动关闭。

| 知识权限 | 不超过来源授权范围 | 阻止发布或访问 |

## 14. 补偿流汇总

| 原业务结果 | 补偿动作 | 不允许的处理 | 补偿后要求 |
|---|---|---|---|
| 线索误合并 | 撤销合并并恢复原关系 | 删除原录入和历史 | 原线索、联系人和误合并轨迹均可查 |
| 财务事实录错 | 新增更正记录并重算影响 | 覆盖原金额且无原因 | 财务复核并通知项目 |
| 项目计划变更 | 形成新基线和影响确认 | 覆盖原计划 | 原基线、原因和确认人保留 |
| 工单误关闭/结果不足 | 窗口内重开或新建关联工单 | 静默改回处理中 | 原关闭和新处理轨迹均保留 |
| 会议变更 | 重新确认并更新原飞书事件 | 重复创建多个事件 | 同一事件引用、排期和参与人一致 |
| 绩效申诉改分 | 重新锁定并触发工资重算 | 覆盖原评分和申诉 | 原结果、申诉和新结果可解释 |
| 工资条错误 | 财务复核后发布更正版本 | 删除原工资条 | 员工可区分原版与更正版 |
| 知识撤权/错误 | 停采、下架、纠错或新版本 | 继续返回过期/越权内容 | 来源、版本和治理原因保留 |

## 15. 已确认恢复方案与延续推定

用户已确认采用以下5项恢复方案，现作为正式业务规则：

1. 已保存业务记录错误时采用更正记录恢复，而不是覆盖原记录（EX-GEN-005）。
2. 线索误合并时允许授权业务角色撤销合并并恢复原关系（EX-LEAD-005）。
3. 财务金额录错时通过更正记录重新计算影响（EX-FIN-005）。
4. 工资条发布后发现错误时发布更正版本并保留原版（EX-PAY-006）。
5. 工作时限自动计算依赖有效公司工作日历；配置缺失时暂停自动到期结论（EX-GEN-008）。

EX-OPS-006继续沿用此前已标注的“全域审计与变更记录”推定主题，是本阶段唯一未单独确认的延续推定；它只限制审计下钻不得扩大原业务权限，不改变业务范围。
