# 人事闭环 · 前端对接说明

> 给前端。对应二期 PRD **G2-003**。前缀 `/api/v1`，字段以 `http://127.0.0.1:8000/docs` 为准。  
> 员工档案、任职历史、飞书考勤汇总还是走现有 `/org/employees*`，不要重写。  
> **页面怎么摆、按钮怎么点：** 打开 [`docs/g2-003-hr-prototype.html`](../g2-003-hr-prototype.html)（可点原型，按这个做）。

---

## 1. 业务一句话

合同、假勤、转岗离职、工资条都在系统里走完。到期要能提前看到；人走了，名下线索/任务/资产清完才能关掉账号。

| 角色 | 权限码 | 用哪些页 |
|------|--------|----------|
| 员工 | 登录即可 | 假勤申请、本人工资条、本人合同 |
| 人事 / 综合管理 | `org:view` `org:manage` | 合同台账、转岗离职、假勤余额、人事看板 |
| 财务 | `payment:view` | 工资条全量、更正 |

主管看本部门工资明细还没定（PRD D2），先不做部门工资条。

## 3. 接口（前缀 `/api/v1`）

### 劳动合同

| 操作 | 接口 |
|------|------|
| 台账 | `GET /hr/contracts?department_id=&status=&employee_id=` |
| 新建 | `POST /hr/contracts` |
| 详情 | `GET /hr/contracts/{id}` |
| 编辑 | `PATCH /hr/contracts/{id}` |
| 续签 | `POST /hr/contracts/{id}/renew` |
| 到期预警 | `GET /hr/contracts/expiring?days=90`（含试用期 30 天内） |
| 扫描件 | `GET /hr/contracts/{id}/file` → `{url, expires_in}` |

合同类型建议：`fixed` / `open` / `intern` / `labor`。  
状态：`pending_sign` / `signed` / `renewed` / `terminated` / `cancelled`（续签审批驳回或撤回）。

续签约定：

- 仅 `signed` 可续签；审批中旧合同保持 `signed`，新合同为 `pending_sign`（`supersedes_id` 指向旧合同）。
- 列表/详情字段 `renew_pending: bool`：旧合同上有进行中的续签新单时为 `true`，此时禁用「续签」按钮，展示「续签审批中」。
- 审批通过：新合同 `signed`，旧合同 `renewed`。驳回/撤回：新合同 `cancelled`，旧合同不变，可再次发起续签。
- 台账默认可过滤掉 `renewed` / `cancelled`，历史用详情版本链看。

列表/详情附件字段（与项目里程碑约定一致，前端可直接展示）：

| 字段 | 说明 |
|---|---|
| `file_path` | 原存储路径（兼容） |
| `attachment` | 展示文件名；未单独传时取路径末段 |
| `attachment_path` | 同 `file_path`，给 `parseAttachmentList(attachment, attachment_path)` |

上传扫描件：`POST /uploads`，`category=labor_contract`（需要 `org:manage`），把返回的 `path` 写进 `file_path` 或 `attachment_path`；可选再传 `attachment` 作为展示文件名。

### 转岗

| 操作 | 接口 |
|------|------|
| 列表 | `GET /hr/transfers` |
| 申请 | `POST /hr/transfers`（`employee_id, to_department_id, effective_on, reason, job_title?`） |
| 详情 | `GET /hr/transfers/{id}` |

有已发布的 `hr_transfer` 规则就进审批中心；测试环境没规则会直接改部门并写任职历史。

### 离职交接

| 操作 | 接口 |
|------|------|
| 列表 | `GET /hr/resignations` |
| 发起 | `POST /hr/resignations` |
| 详情 | `GET /hr/resignations/{id}`（带 `handover_id`） |
| 交接单 | `GET /hr/handovers/{id}`（`items` + `open_items` + `can_complete`） |
| 指定接收人 | `POST /hr/handovers/{id}/items/{item_id}/assign` `{"assignee_id"}` |
| 接收人确认 | `POST /hr/handovers/{id}/items/{item_id}/confirm` |
| 完成交接 | `POST /hr/handovers/{id}/complete`（检查未过返回 400） |

交接项 `kind`：`lead` / `customer` / `opportunity` / `task` / `ticket` / `asset` / `approval` / `schedule`。  
资产不能转交，名下还有资产时 `can_complete=false`。完成后账号禁用、委托收回。

### 假勤

| 操作 | 接口 |
|------|------|
| 列表 / 提交 | `GET/POST /hr/leave-requests` |
| 详情 | `GET /hr/leave-requests/{id}` |
| 余额 | `GET /hr/leave-balances?employee_id=&year=` |
| 配置额度 | `POST /hr/leave-balances?employee_id=&leave_type=annual&quota=5` |
| 调入结转 | `PATCH /hr/leave-balances/{id}` |
| 月度汇总 | `GET /hr/attendance/monthly?user_id=&month=2026-09` |

`leave_type`：`annual` / `sick` / `personal` / `overtime` / `makeup` / `field`。年假等会扣余额。

### 工资条

| 操作 | 接口 |
|------|------|
| 本人列表 | `GET /payslips/me` |
| 明细 | `GET /payslips/{id}` |
| 下载 | `GET /payslips/{id}/download` |
| 财务全量 | `GET /payslips?period_label=2026-08` |
| 更正 | `POST /payslips/{id}/correct`（出新版本，旧版保留） |

绩效「发布工资」后会按考核单自动生成工资条（固定工资本期为 0，绩效工资取奖金；财务用更正补固定工资和加减项）。

### 看板

`GET /hr/dashboard`：在职人数、本月入离职、合同 90/30/7 天到期、工时、未完成交接、当月工资合计。
