# 知识库治理 + 智能助手 · 前端对接说明

> 给前端。后端接口已具备（前缀 `/api/v1`），字段以 `http://127.0.0.1:8000/docs` 为准。  
> **员工提问走右下角智能助手，不要再把知识库页当成主问答入口。**  
> 知识库给管理员管来源和发布。

---

## 1. 业务一句话

管理员把制度接进来并**发布**，员工只在**智能助手**里问。助手只搜已发布知识；没有依据就拒答，不能编。

两种人：

| 角色 | 权限码 | 用哪些页 |
|------|--------|----------|
| 员工 | `knowledge:view` | 智能助手（问问题） |
| 知识管理员 | `knowledge:manage` | 知识库工作台 + 下文新页 |

## 2.0 原型三页（按截图对接，优先做这些）

前缀 `/api/v1`。权限：目录/列表 `knowledge:view`；新建、审核、飞书配置 `knowledge:manage`。  
员工列表接口**只返回已发布**；管理员可按 `status` 筛全部。附件最多 5 个。

### 企业知识库（目录 + 列表 + 新建文档）

| 操作 | 接口 |
|------|------|
| 打开页 / 左侧目录 | `GET /knowledge/workbench`（`spaces` 即目录，含「全部文档」「合规知识」等） |
| **新增知识库目录** | `POST /knowledge/spaces` `{ "name", "code?", "icon?", "description?" }`（需 `knowledge:manage`；`code` 不传则自动生成；不可用 `all`） |
| 文档列表 | `GET /knowledge/entries?space_id=&keyword=&status=&page=&page_size=` |
| 搜标题/摘要/正文 | 同一接口的 `keyword`；员工侧会强制只看 `published` |
| 预览一篇 | `GET /knowledge/entries/{id}` |
| **删除文档** | `DELETE /knowledge/entries/{id}`（需 `knowledge:manage`，不可恢复） |
| **保存草稿** | `POST /knowledge/articles` `{ "action": "draft", ... }` |
| **提交审核** | 新建：`action: "submit"`；已有草稿：`POST /knowledge/entries/{id}/submit` |
| **直接发布（管理员）** | `{ "action": "publish" }`（默认，不传也是发布） |
| 再改草稿 | `PATCH /knowledge/entries/{id}`（仅 `draft`） |
| **上传附件** | `POST /uploads` `multipart`：`file` + `category=knowledge`（需 `knowledge:manage`） |
| **下载附件** | `GET /knowledge/entries/{id}/attachments/{index}/download`（需 `knowledge:view`；`index` 从 0 起，对应条目 `attachments` 数组下标） |

`POST /knowledge/articles` body：

```json
{
  "space_id": 1,
  "title": "文档标题",
  "content": "正文",
  "doc_type": "qa",
  "keywords": "研报,开发,市场",
  "source_url": "https://xxx.feishu.cn/docx/...",
  "action": "draft",
  "attachments": [
    { "filename": "说明.pdf", "path": "knowledge/uuid_说明.pdf" }
  ]
}
```

`doc_type`：`qa`（Q&A问答）/ `doc`。`keywords` 当标签（逗号分隔）。`source_url` 可选飞书链接。  
附件：先 `POST /uploads` 拿到 `{ filename, path, url }`，再写入 `attachments`（最多 5 个）。创建和 `PATCH` 草稿都能带。条目返回 `attachments: [{ filename, path, url, download_url }]`。  
下载走带鉴权的 `download_url`（不要直接打开静态 `/uploads/...`）：`responseType: 'blob'`，用返回头里的文件名保存。员工只能下已发布文档的附件。

`status`：`draft` / `pending_review` / `reviewed` / `published` / `disabled` / `archived` / `rejected`  
`origin`：`manual` 人工录入；`feishu_doc` 飞书文档同步；`feishu_chat` 飞书会话抓取  
`source`：列表「来源」展示文案（已拼好，优先 `source_label`）；筛选用 `origin`  
`source_label`：库里的来源文案（可与 `source` 相同）

### AI 草稿审核工作台

| 操作 | 接口 |
|------|------|
| 打开列表（待审 AI 草稿） | `GET /knowledge/entries?status=pending_review&origin=ai` |
| 筛来源 | `origin=feishu_doc` 或 `origin=feishu_chat` |
| 待审条数 | 用列表 `total`，或 `GET /knowledge/stats` 的 `pending_review` |
| **预览** | `GET /knowledge/entries/{id}` |
| **直接通过** | `POST /knowledge/entries/{id}/approve` body `{}` |
| **编辑后通过** | `POST /knowledge/entries/{id}/approve` `{ "title", "content", "summary?" }` |
| **拒绝入库** | `POST /knowledge/entries/{id}/reject` |

飞书同步拉下来的文档现在是 **待审核草稿**（`origin=feishu_doc`），助手搜不到，必须通过后才入库。

附件：保存/发布时后端会抽 PDF 文本、图片 OCR，写入 `attachment_text`（不改用户正文）；助手检索与回答会用到。已有附件条目在首次被提问时会补抽一次。

### 飞书同步配置（管理员）

| 操作 | 接口 |
|------|------|
| 打开页 | `GET /knowledge/sync-config` |
| 抓取总开关 | `PATCH /knowledge/sync-config` `{ "crawl_enabled": true/false }` |
| 添加飞书群白名单 | `POST /knowledge/sync-config/chats` `{ "name", "external_ref" }`（群 ID） |
| 添加文件夹/文档白名单 | `POST /knowledge/sync-config/folders` `{ "name", "external_ref", "space_id?" }` |
| 移除白名单 | `DELETE /knowledge/sync-config/{source_id}` |

`GET /knowledge/sync-config` 返回：

```json
{
  "crawl_enabled": true,
  "chats": [{ "id": 1, "name": "销售-客户对接群", "external_ref": "oc-xxxx1", "status": "active", "authorized": true }],
  "folders": [{ "id": 2, "name": "产品方案库", "external_ref": "fold-xxx2", "status": "active", "authorized": true }]
}
```

`authorized && status==active` 展示「已开启」。关闭总开关后，工作台再接入飞书文档**不会自动出草稿**；白名单本身还在。  
群会话抓取只落白名单，不会真去拉群消息。

## 2.1 业务先后顺序（每一步调哪些接口）

前缀 `/api/v1`。一条知识从接入到被问到，按这个走。

```
来源台账 → 任务监控（可选）→ 条目治理 → 智能助手 → 问答反馈 → 待补知识 → 运营统计
```

工作台 `/knowledge` 是现成的接入/录入入口，和新页并行，不插入成单独一步。

### 第 1 步 · 来源台账（先接入）

| 操作 | 接口 |
|------|------|
| 打开列表 | `GET /knowledge/sources` |
| 点进一条 | `GET /knowledge/sources/{id}` |
| 看同步状态 | `GET /knowledge/sources/{id}/sync-status` |
| 接入飞书/手工 | `POST /knowledge/sources`（飞书会自动同步） |
| 以后再拉一次 | `POST /knowledge/sources/{id}/resync` |
| 失效 | `POST /knowledge/sources/{id}/revoke` |

现有工作台等价操作：`GET /knowledge/workbench`、`POST /knowledge/sources`、`POST /knowledge/sources/{id}/authorize`。

### 第 2 步 · 任务监控（同步出问题才来）

| 操作 | 接口 |
|------|------|
| 打开任务列表 | `GET /knowledge/jobs` |
| 失败重试 | `POST /knowledge/jobs/{id}/retry` |

### 第 3 步 · 条目治理（必须发布，助手才能搜到）

| 操作 | 接口 |
|------|------|
| 打开列表（筛待审核） | `GET /knowledge/entries?status=pending_review` |
| 点开一篇 | `GET /knowledge/entries/{id}` |
| 审核通过 | `POST /knowledge/entries/{id}/review` |
| **发布** | `POST /knowledge/entries/{id}/publish` |
| 停用 | `POST /knowledge/entries/{id}/disable` |
| 归档 | `POST /knowledge/entries/{id}/archive` |
| 看版本 | `GET /knowledge/entries/{id}/versions` |
| 纠错提交 | `POST /knowledge/entries/{id}/corrections` |

现有工作台手工录入仍是 `POST /knowledge/articles`（直接发布，跳过本步审核）。

### 第 4 步 · 智能助手（员工提问）

| 操作 | 接口 |
|------|------|
| 打开助手 | `GET /agent/conversations` |
| 点历史会话 | `GET /agent/history/{id}` |
| **发送问题** | `POST /agent/chat`（前端只打这个） |
| 后端搜知识 | Agent 内部 `search_knowledge` ≈ `POST /knowledge/ask`（前端不要调） |
| 写操作确认 | `POST /agent/confirm` |

### 第 5 步 · 问答反馈（问过之后）

| 操作 | 接口 |
|------|------|
| 员工点有用/无用/纠错 | `POST /knowledge/ask/{ask_id}/feedback` |
| 管理员打开队列 | `GET /knowledge/feedback` |
| 采纳 / 驳回 | `PATCH /knowledge/feedback/{id}` |

### 第 6 步 · 待补知识（经常问不到）

| 操作 | 接口 |
|------|------|
| 打开清单 | `GET /knowledge/gaps` |

看完再回到第 1 / 3 步补来源或发布条目。

### 第 7 步 · 运营统计（最后看数）

| 操作 | 接口 |
|------|------|
| 打开看板 | `GET /knowledge/stats` |

## 3. 已有页：智能助手

路由：全局悬浮，不换页。

进窗：`GET /agent/conversations`  
点历史某条：`GET /agent/history/{会话id}`

| 按钮 / 操作 | 接口 | 说明 |
|-------------|------|------|
| 打开助手 | `GET /agent/conversations` | 拉会话列表 |
| 历史 → 选一条 | `GET /agent/history/{id}` | 灌入旧消息 |
| 新会话 | 无 | 本地清空 |
| 关闭 | 无 | 收起 |
| **发送**（Enter） | `POST /agent/chat` | **唯一提问接口**。制度/流程由后端搜知识，前端不要再调 `/knowledge/ask` |
| 写操作确认框 → 确定 | `POST /agent/confirm` `{ "confirmed": true }` | 改负责人、通过审批等 |
| 确认框 → 取消 | `POST /agent/confirm` `{ "confirmed": false }` | |

`POST /agent/chat` 请求体与现在一致：`message`、`conversation_id?`、`page_context`。SSE。

**建议补（现没有）：** 答案下方三个按钮，`ask_id` 若 SSE 里没有可先不做。

| 按钮 | 接口 |
|------|------|
| 有用 | `POST /knowledge/ask/{ask_id}/feedback` `{ "kind": "useful" }` |
| 无用 | `{ "kind": "useless" }` |
| 纠错 | `{ "kind": "correction", "content": "说明" }` |

## 4. 已有页：知识库工作台

路径：`/knowledge`  
进页：`GET /knowledge/workbench`

| 按钮 / 操作 | 接口 | 说明 |
|-------------|------|------|
| 打开页面 | `GET /knowledge/workbench` | |
| 点左侧知识空间 | 无 | 本地筛选 |
| 接入飞书文档（打开弹窗） | 无 | |
| 弹窗「取消」 | 无 | |

## 5. 新页：来源台账

进页：`GET /knowledge/sources?status=&page=&page_size=`  
返回：`{ total, items }`

| 按钮 / 操作 | 接口 |
|-------------|------|
| 打开 / 筛选 / 翻页 | `GET /knowledge/sources` |
| 点某一行 | `GET /knowledge/sources/{id}` |
| 刷新同步状态 | `GET /knowledge/sources/{id}/sync-status` |
| 重新同步 | `POST /knowledge/sources/{id}/resync` |
| 失效 / 撤销授权（二次确认） | `POST /knowledge/sources/{id}/revoke` |
| 接入新来源（若做在本页） | `POST /knowledge/sources`（同工作台） |

## 6. 新页：条目治理（核心）

### 6.1 列表

进页：`GET /knowledge/entries`

Query：`status`、`space_id`、`source_id`、`keyword`、`page`、`page_size`  
返回：`{ total, items }`

建议 Tab 与 `status`：

| Tab | status |
|-----|--------|
| 待审核 | `pending_review` |
| 已审核 | `reviewed` |
| 已发布 | `published` |
| 已停用 | `disabled` |

点行进详情：`GET /knowledge/entries/{id}`（含 `chunks` 分块）。

### 6.2 详情按钮（按状态显隐）

| 按钮 | 接口 | 可点状态 |
|------|------|----------|
| 审核通过 | `POST /knowledge/entries/{id}/review` | `pending_review` |
| 发布 | `POST /knowledge/entries/{id}/publish` | `pending_review` / `reviewed` / `disabled` |
| 停用 | `POST /knowledge/entries/{id}/disable` | `published` |
| 归档 | `POST /knowledge/entries/{id}/archive` | 非 `archived` |
| 版本记录 | `GET /knowledge/entries/{id}/versions` | 随时 |
| 纠错（打开表单） | 无 | |
| 纠错提交 | `POST /knowledge/entries/{id}/corrections` | body：`content`（必填），`title?`，`summary?`，`reason?` |

纠错后状态回到 `pending_review`，旧版本进版本列表。必须再点审核、发布，助手才会用新正文。

**只有「发布」之后，员工在助手里才能搜到这篇。**

## 10. 状态机（条目）

```
draft --提交审核--> pending_review --审核--> reviewed --发布--> published
                         \                    |
                          \----approve/发布----/
                                              |
新建也可 action=publish 直接发布（跳过草稿/审核）
                                              |
                         disable <------------+
                         reject（仅待审核）
                         archive（任意非归档）
草稿不进审核页；须先 submit 成 pending_review
纠错：任意 --> pending_review（并写入 versions）
飞书同步：出 origin=feishu_doc 的 pending_review，approve 后入库
```

助手检索条件：`status = published`，且来源未失效。

## 11. 不要做错的几件事

1. 员工提问只打 `POST /agent/chat`，不要再给助手接 `/knowledge/ask`。  
2. 「接入飞书」提交后已经同步，不要引导用户立刻再点同步。  
3. 工作台「拉取飞书」现在出的是待审核草稿，不是直接发布；`POST /articles` 不传 `action` 仍直接发布。  
4. 已发布正文禁止用一个「保存」去 PATCH 覆盖；改内容走纠错。草稿才用 `PATCH /entries/{id}`。  
5. 联调看 Swagger，不要把文档里的路径当假数据契约写死后不改。

## 12. 建议开工顺序（和业务顺序不同）

业务上先接入再审核再提问。前端先做「能发布」，否则验不了闭环。

| 开工顺序 | 页面 | 先接这些接口 |
|----------|------|----------------|
| 1 | 条目列表 + 详情 | `GET /entries`、`GET /entries/{id}`、`POST .../review`、`publish`、`disable` |
| 2 | 来源台账 | `GET /sources`、`GET /sources/{id}`、`GET .../sync-status`、`POST .../resync`、`revoke` |
| 3 | 任务监控 | `GET /jobs`、`POST /jobs/{id}/retry` |
| 4 | 问答反馈、待补知识 | `GET/PATCH /feedback`、`POST /ask/{id}/feedback`、`GET /gaps` |
| 5 | 运营统计 | `GET /stats` |
| 6 | 助手有用/无用 | `POST /ask/{ask_id}/feedback`（可等 SSE 带 `ask_id`） |

助手 `POST /agent/chat` 已能搜已发布知识，不必等新页做完员工才能问。
