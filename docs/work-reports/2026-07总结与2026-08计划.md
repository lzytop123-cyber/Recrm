## 一、岗位说明（汇报口径）

本人在**市场部**，职责侧重**技术落地**：把销售、交付、财务协同中的流程规则，做成系统里可执行、可审批、可统计的能力。

工作价值不按「写了多少代码」衡量，而按：

1. **流程是否跑通**（认领 → 到账 → 核销 → 验收 → 结项）
2. **权责是否清晰**（谁能看、谁能批、首页谁能进）
3. **经营数据是否可信**（看板与合同/回款/交付状态一致）

## 二、7 月工作总结

### 2.1 总体结论

7 月围绕 CRM 经营闭环做了三件事：**经营可视、财务闭环、交付验收闭环**，并统一把关键节点接入**审批中心**，减少「页面里直接点过、事后无法追溯」的情况。

### 2.2 重点成果

#### （1）经营总览与权限可控

- 经营总览按经营看板方向改版，聚合合同、回款、交付等经营信号，服务管理层与一线一眼看状态。
- 补齐 `dashboard:view` 权限：经营总览改为**可配置**，可在「系统管理 → 角色权限」中按角色开通/关闭，避免「登录就能看全盘」。
- 仅录入岗、销售、管理层等角色首页与菜单边界继续收紧，减少无关入口干扰。

#### （2）合同财务闭环：认领 → 确认到账 → 核销审批

- 明确两步语义：
  - **确认到账**：证明钱已到账；
  - **核销**：多期分期下把钱分到具体应收期次。
- **核销纳入审批中心**：提交核销方案后进入待审，通过后才计入应收已收；待审占用可用余额，避免重复核销。
- 到款列表体验收敛：「提交到款认领」仅在「到款核销」页签展示，合同台账 / 应收计划不再误导操作。

#### （3）项目交付「内部验收」按原型落地，并走审批

- 对齐原型：验收结论、方式、负责人、遗留安排、**验收附件必填**。
- 流程定为：

  > 执行中 → 提交验收 → **审批中心通过** → 已验收 → 财务核对 / 关闭遗留 → 结项

- 结项门槛落地：验收审批通过 + 财务核对通过 + 遗留关闭（无遗留则视为已关闭），避免「已验收就能直接结项」。

#### （4）审批中心能力扩展（业务侧统一入口）

本月审批中心已覆盖/增强的类型包括（按业务）：

| 类型 | 业务含义 |
|------|----------|
| 合同审批 | 销售合同 |
| 到款认领复核 | 财务确认到账 |
| 收款核销 | 分期核销到应收 |
| 内部验收 | 项目交付验收 |
| 工时 / 资产借用等 | 既有项目与资产协同 |

技术侧与市场侧的交集点：**把市场部关心的「合同—回款—交付完成」关键动作，收敛到同一审批入口**。

#### （5）其他支撑

- 组织权限边界、库表迁移与环境稳定性等底座工作持续推进，保证业务功能可上线、可回归。
- 高保真原型与系统实现对照验收（财务、交付验收等），减少「原型有、系统没有」的落差。

### 2.3 不足与反思

1. **审批中心权限偏窄**：目前菜单侧偏管理员；财务、交付负责人日常批核销/验收，入口体验还可再顺。
2. **财务核对仍偏人工确认**：结项前财务核对已可点通，与真实账务系统的自动对账尚未对接。
3. **培训与操作手册未同步**：流程变了（核销、验收都要审批），一线同学需要一页纸操作说明，否则容易仍按旧习惯「只点确认到账」。
4. **个人在市场部的「技术翻译」还要加强**：功能上线后，需用市场语言讲清「解决了什么协作痛点」，而不仅是「上了什么接口」。

## 三、8 月工作计划

### 3.1 目标一句话

**把 7 月打通的闭环用稳、用懂、用准**：补操作体验与权限、补结项与财务协同、补数据质量与培训，服务市场部 8 月经营动作。

### 3.2 重点计划（按优先级）

| 优先级 | 事项 | 产出 | 预计 |
|--------|------|------|------|
| P0 | 核销 / 验收审批**操作手册 + 现场演示**（销售、财务、交付） | 1 页 SOP + 演示记录 | 第 1 周 |
| P0 | 审批中心**角色可见性**：财务/交付负责人可进待办（不必全员 admin） | 权限与菜单调整 | 第 1–2 周 |
| P1 | 验收与结项体验打磨：待办深链、列表状态文案、驳回后重提路径 | 可验收的一轮体验清单 | 第 2 周 |
| P1 | 经营总览按角色核对指标口径（回款、待核销、待验收） | 口径说明 + 修正项 | 第 2–3 周 |
| P2 | 财务核对与合同回款数据联动（减少纯手工勾选） | 方案或一期联动 | 第 3–4 周 |
| P2 | 退款 / 冲销等是否进审批中心（与财务对齐规则） | 规则结论 | 第 4 周 |
| 持续 | 缺陷收敛、原型对照缺口、配合市场活动期系统稳定 | 周更问题清单 | 全月 |

### 3.3 与市场部业务的对齐方式

8 月建议固定两个对齐节奏（可并入部门例会）：

1. **周初 15 分钟**：本周要上线的流程变更（谁受影响、怎么操作）。
2. **月末 30 分钟**：闭环数据抽检——抽几笔合同看「认领—核销—验收—结项」是否断链。

本人承诺输出用**业务语言**写的变更说明，避免只丢技术更新日志。

### 3.4 个人能力与协作

- 加深对市场漏斗、分期回款、交付里程碑的业务理解，技术方案先问「业务能不能批、数据能不能信」。
- 与财务、交付、销售接口人保持短反馈环；争议规则先对齐再改系统。
- 保持「最小可用上线 → 审批可追溯 → 再增强」的节奏，避免一次堆太多配置。

## 四、需要部门支持的事项

1. **明确审批角色**：核销默认谁批、验收默认谁批（管理层 / 财务 / 交付负责人），便于配权限。
2. **指定 1–2 名业务验收人**：8 月对「到款核销」「内部验收」做实操验收，通过后再大范围推广。
3. **培训窗口**：希望安排一次 20–30 分钟部门内演示（可录屏）。

---

## 五、一句话收束

**7 月**：把市场经营关键链路（回款核销、项目验收）做成可审批、可配置、可结项约束的系统能力。  
**8 月**：把这些能力推到「人人会用、口径一致、审批顺畅」，真正服务市场部月度经营复盘与执行。
