## 一、权限怎么生效（对齐口径）

| 层级 | 说明 |
|------|------|
| 左侧菜单 | 后端按权限码裁剪后返回；无权限的菜单不显示 |
| 路由访问 | 前端路由再拦一道；无权限会提示并跳转首页 |
| 操作按钮 | 另有权限码（如 `lead:manage`、`contract:approve`）；能进页面 ≠ 能点所有按钮 |
| 系统管理员 | `admin` 角色直接放行全部 |
| 数据范围 | 角色有**默认范围**（公司 / 本部门 / 仅本人）；可在「系统管理 → 编辑角色」按模块覆盖。列表/详情按模块解析：只统计**拥有该模块权限**的角色，取 `module_scopes[模块]` 或默认范围，再取最宽。一人多角色时，不再用全局最宽范围套到所有模块。 |

> 登录/菜单接口返回的 `data_scope` 仍为角色默认范围的最宽值，仅作展示；业务过滤以服务端 `resolve_data_scope(user, module)` 为准。

## 四、预置角色权限包

| 角色 | code | 数据范围 | 默认可见菜单 | 对齐要点 |
|------|------|----------|--------------|----------|
| 系统管理员 | `admin` | 全公司 | 全部菜单（含系统管理） | 权限码全部放行；角色权限不可改 |
| 董事会 | `board` | 全公司 | 总览/待办/审批/销售/合同/项目/交付/工单/排期/员工 | 偏查看+关键审批；无固定资产、无系统管理 |
| 管理层 | `executive` | 全公司 | 总览/待办/审批/销售/合同/项目/交付/工单/排期/资产/员工 | 可分配线索池（`lead:manage`）；无系统管理 |
| 中层管理 | `middle_manager` | 本部门 | 同管理层菜单 | 数据范围限部门；可管理知识库 |
| 销售 | `sales` | 本部门 | 总览/待办/销售/合同 | 无审批中心、无项目交付、无工单排期；不可看待分配线索池 |
| 交付负责人 | `delivery_lead` | 本部门 | 总览/待办/审批/合同/项目/交付/工单/排期 | 无销售中心（无 `lead:view`） |
| 运营 | `operations` | 本部门 | 总览/待办/审批/项目/交付/工单/排期/资产 | 无销售、无合同 |
| 开发 | `developer` | 仅本人 | 总览/待办/项目/交付/工单 | 执行侧最小集 |
| 讲师主播 | `instructor` | 仅本人 | 总览/待办/项目/交付/排期 | 无工单 |
| 财务 | `finance` | 全公司 | 待办/审批/线索录入/合同/项目/交付 | 收款全权限；无经营总览；首页偏线索录入 |
| 部门负责人 | `dept_head` | 本部门 | 总览/待办/审批/线索录入/合同/项目/交付/工单/排期 | 仅线索录入岗，不进完整销售中心 |
| 品宣专员 | `brand` | 本部门 | 待办/线索录入/排期 | 最小录入+排期 |
| 综合管理主管 | `hr_supervisor` | 全公司 | 待办/审批/线索录入/工单/排期/员工 | 组织可见；无经营总览 |
| 资产管理员 | `asset_admin` | 全公司 | 待办/审批/线索录入/资产 | 资产为主 |
| 普通员工 | `employee` | 仅本人 | 待办/线索录入/工单/排期/资产 | 无总览、无销售全链路、无项目合同 |

## 五、建议和领导确认的差异点

1. **销售**默认无审批中心、无项目/交付菜单。  
2. **财务**无经营总览，走「线索录入」而非销售中心。  
3. **部门负责人 / 品宣 / 综合管理主管 / 资产管理员 / 普通员工**同属「仅线索录入岗」。  
4. **系统管理**默认只有系统管理员。  
5. **目标绩效（OKR）**二期隐藏，侧栏不出现。
