# 当前入口更新：日常简版

当前 `frontend.html` 已使用“发起考核（可多部门）→ 员工各自提交 → 各部门主管并行评分 → 结果确认 → 已完成”。发起页改为可见的三步工作台：可多选已发布模板，按部门核对人员，统一定截止日期后一次批量发起；每个模板生成独立批次。

## 简版完整体验

1. HR在「本期考核」页勾选一个或多个已发布模板（默认含市场 / 运维 / 内容演示模板）；系统按各模板适用部门、岗位、任职条件和重复考核规则分别匹配人员。
2. HR按部门批次核对人员：自动匹配默认勾选；试用期、在岗天数不足或长期休假人员默认排除；已有相同考核的人员直接阻断。手动排除或纳入时必须填写原因。
3. HR设置员工提交、主管评分和结果确认截止日期（对全部批次生效）；需要时展开可选 HR 复核。点击“检查并批量发起”后，为每位员工保存部门、岗位、主管、任职状态和人工调整原因快照。
4. 发起后总览展示「按部门进度」看板与全员名单；每个人独立推进，各部门主管并行评分。演示可用“快进到期末”。
5. 切换员工，在同页补充缺失材料、核对系统数据、填写工作说明后提交。其他员工与其他部门进度不受影响。
6. 切换主管，核实材料并评分；某条材料不完整可针对该条退回。
7. 若启用HR复核，评分后由HR复核；未启用则直接通知员工。员工无异议确认后自动完成。
8. 有异议时员工提交申诉，由HR复核后再确认。

# 当前入口更新：日常简版（历史）

当前 `frontend.html` 已使用“发起考核 → 员工提交 → 主管评分 → 结果确认 → 已完成”，下方原13步说明仅对应 `frontend-reference.html` 历史参考页。

“考核模板管理”现已补充完整交互：HR可新建或复制模板、维护基本信息和指标、查看校验问题并试算；业务负责人可审核通过或填写原因退回；HR发布后模板进入发起考核下拉框。已发布模板不可直接修改，只能复制新版本；停用不影响历史考核。详细页面、状态、字段、接口建议和验收项见 `前端交付说明.md`。

## 简版完整体验（历史单模板）

1. HR点击“发起本期考核”，先选择周期和已发布模板；系统按模板的适用部门、岗位、任职条件和重复考核规则生成候选人员。
2. HR核对人员匹配结果：自动匹配默认勾选；试用期、在岗天数不足或长期休假人员默认排除；已有相同考核的人员直接阻断。HR手动排除或纳入时必须填写原因。
3. HR设置员工提交、主管评分和结果确认截止日期；默认无需HR结果复核，需要时展开可选设置勾选。点击“检查并发起”后，为每位员工保存当时的部门、岗位、主管、任职状态和人工调整原因快照。
4. 发起后可随时查看目标。为方便演示，HR可点击“演示快进到期末”；这不是正式业务的审批步骤。
5. 切换员工和要体验的姓名，在同页补充缺失材料、核对系统数据、填写工作说明。可保存草稿，也可直接一次提交。其他员工进度不受影响。
6. 切换主管，展开材料核实并评分，勾选已核实后发布。某条材料不完整可针对该条退回，其他材料及说明保留。
7. 若启用HR复核，评分后由HR复核；未启用则直接通知员工查看结果。员工无异议确认后自动完成，不再由HR另点结束。
8. 有异议时员工提交申诉，由HR复核后再确认。本原型仅演示“维持原分”；改分需要重新评分与复核，不在此直接修改。

员工首页仅展示自己的当前待办，HR/主管总览显示全员进度；完整流程和处理记录折叠，避免默认铺满13个步骤。已保存草稿刷新后保留，未保存输入离开页面会丢失。原版已发起的进度会接续，原HR复核要求保留；原版已确认待结束的结果转为自动完成。不会删除旧版缓存，不改后端或Vue工程。

# 绩效原型优化说明

旧版参考入口：同目录 `frontend-reference.html`。请将HTML、`frontend-flow.css`、`frontend-flow.js`放在同一目录；可直接用浏览器打开。旧版已保存在 `frontend-before-optimization.html`。

## 本版重点

- 用张明的9月市场考核贯穿全流程，列表、详情、评分和归档始终指向同一人。
- 右上角切换员工、主管、HR、培训负责人；菜单随角色变化，下一步显示具体处理人和动作。
- 首页分三段呈现13个环节：开始前先定标准与安排，执行中按目标工作并准备资料，期末复核、确认和结束考核。当前处理人、完成条件和下一步入口始终可见。
- 发起前的5个准备环节均可实际操作，不能跳过：HR制定标准、主管确认标准、HR设置本期安排、员工知晓目标、HR启动前检查。
- “收集数据”改称“准备考核资料”；“归档”以“结束考核并锁定结果”说明，完成状态为“考核已完成”。
- 正常流程、退回补证据、退回评分、结果申诉分别有对应状态；不能只弹成功提示而不更新进度。
- 正式模板草稿与一套合成演示模板分开。演示模板也从未制定状态开始，经确认后生效。13套正式草稿按岗位与阶段呈现，展示指标、目标和冲突，可暂存指标讨论方案及意见。
- 员工打开本人详情，不进入主管编辑页；系统指标只读，主管评价填写分数和依据。
- 数据台账使用中文指标，补证据与审核能推动主流程。导入是独立合成示例，明确排除错误行后再确认，不影响主案例。
- 入职阶段按业务/职能岗和第5天/第1月/第3月切换完整维度；未确认规则只允许暂存。
- 讲师反馈先记录、后核实，未确认加减分不直接入账或影响工资。
- 归档结果与工资依据分开展示，缺工资基数不等于考核本身不能归档。

## 推荐演示顺序

1. HR：点击“制定考核标准”，查看11项指标，设置模板名称与签约目标，勾选已查看口径，提交主管确认。
2. 主管：查看标准，确认并锁定V1；也可填写原因退回修改。
3. HR：设置本期考核对象、主管、复核人及各环节截止日，保存并告知员工。演示固定9月考核，期末处理截止日在10月，可调整但必须顺序合理。
4. 员工：查看期初目标和安排，勾选确认已知晓；也可反馈疑问，由HR重新设置并再次告知。
5. HR：运行启动前检查，确认模板、人员、时间和员工知晓均完成。
6. HR：确认发起9月考核，进入考核进行中。此时没有期末成绩。
7. HR：点击“模拟推进到9月期末”，理解实际业务经过考核期后才准备期末材料。该操作仅推进原型，不修改系统时间。
8. 员工：点击“补充缺少的材料”，查看9条客户材料（6条系统已带入，3条待补）。每条显示已有资料、缺失原因、补充要求及状态。逐条“去补充”，填写内容或“填入演示示例”，保存草稿并返回；全部补齐后“提交材料给HR”。刷新保留已保存草稿，未保存的输入不保留。
9. HR：审核逐客户材料，可以选择某客户“退回此条”，填写具体缺少什么和补充要求。其他材料保留待核实；员工只修改退回项并重新提交，HR核实后全部通过。
10. 员工：核对数据 → 填写工作说明 → 勾选确认 → 提交自评。
11. 主管：填写5项评分，可使用“填入演示评分”，暂存或提交复核。
12. HR：复核，可退回主管或通过并告知员工。
13. 员工：查看结果并确认；也可从详情提交申诉。
14. 如申诉：HR处理申诉，演示核实后维持原分，产生新的结果确认版本；员工再确认。
15. HR：结束考核并锁定结果 → 生成模拟工资依据。

示例分数：系统6项合计69分，主管示例评分22分，总分91；演示绩效基数2000，市场模板系数1.00，模拟绩效金额2000。金额只是合成演示，不涉及实际工资。

上述分数对应默认签约目标4家。若第一步将目标改为5家，在实际签约3家及其余输入不变的情况下，系统指标合计64，总分86，系数0.80，模拟金额1600。目标在制定标准时设置，主管确认后锁定，本期安排会保存该目标。

## 已校正的业务示例

- 拜访16家且新客6家，同时达到15家/新客5家的样例目标，数量项得20分。
- 运维视频42/50=84%，按原分档应得15分，不是18分。
- 105分采用品宣“基础95＋专项10”，不作为没有专项来源的市场结果。
- 品宣强制不合格与工资系数分开解释；造假专项薪酬政策未确认时，不擅自变成零工资。
- 无有效证据不能审核通过；有待处理申诉不能确认和归档；归档后不能再提交评分。

## 演示范围

这是独立的产品流程原型，不是实际前端接入。它不访问后端，不上传真实材料，不执行正式模板批准、人事决定或实际发薪。身份切换用于理解角色分工，不代表真实系统鉴权。

模板草稿支持讨论性编辑与保存，暂不模拟把未确认制度批准为正式版本。入职考核只演示阶段草稿，讲师反馈只演示待核实登记。申诉当前提供“复核后维持原分”分支；改分及重新复核的完整分支未实现。来源证据以合成摘要展示，不伪造可下载的业务附件。

本地状态保存在浏览器localStorage中；不可用时本次页面内仍可演示，但刷新后不保留。本次全流程版使用新的本地进度版本，首次刷新从制定标准开始，不覆盖旧版进度。首页“从第一步重跑”或左侧“从第一步重新演示”会清除本版暂存状态，操作前有确认弹窗。
